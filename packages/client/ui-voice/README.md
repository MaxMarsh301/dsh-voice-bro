# @deepseek-ai/dsh-client-ui-voice

English | [中文](README.zh.md)

Browser UI and audio transport for one Host-managed global voice call. The plugin contributes a compact global-voice launcher to `sidebar.footer.action`, a standard lifecycle, transcript, cancellation, wake-readiness, and cost panel to `conversation.input.dock`, and browser-local calibration to `settings.section`. Push-to-talk and hands-free controls belong to the global voice panel, with no voice buttons in `conversation.input.right`. One root-owned `VoiceSessionController` survives foreground Session changes; the launcher and panel address that same controller.

The plugin creates one `VoiceConsumerId` per browser tab, retains it in session storage across reload and HMR, and rotates a copied value on a fresh tab navigation. It starts the call with the current foreground Session when present. It observes `ctx.sessions.list.current` and publishes later selection changes through `voice.setForeground`. Addressed `voice/creation-requested`, `voice/navigation-requested`, and `voice/completion-requested` events are accepted only when both their consumer id and voice-session id match this page. Creation uses `ctx.workspaces.createSession()` so the target comes only from the explicit, current, or recent accessible Workspace and the normal Host `session.create` policy; it optionally renames through the Session face, subscribes before opening, and reports activation only after the observable current selection contains the new Session within the Host-provided deadline. Each creation id retains its stable acknowledgement payload. Duplicate delivery never creates a second Session and retries an unconfirmed acknowledgement; effect disposal aborts activation waits and removes their subscriptions. Navigation opens the target through `ctx.sessions.open`, verifies the synchronous current selection, and acknowledges that outcome. Completion signals enter a bounded queue and start spoken delivery only while the persistent call is idle. Other tabs and stale calls are ignored.

Pointer down opens the push-to-talk gate and begins microphone/transport setup. Pointer up commits only after the gate captured PCM above the configured voice-activity threshold; an empty, silent, or low-energy noise gate is discarded without `input_audio_buffer.commit` or `response.create`, while one voiced chunk remains sufficient for a short phrase. The plugin buffers gated audio while WebRTC connects, but sends no append before the gate and no buffered audio before both the ordered `oai-events` data channel and Host `sidebandReady` status are ready.

Microphone capture uses an `AudioContext` and inline Blob `AudioWorklet`; dynamic client plugins therefore require no audio asset. The same active context synthesizes a 160 ms wake-confirmation tone locally, without adding it to captured PCM or the WebRTC peer. Mono Float32 input is linearly resampled to signed PCM16 little-endian at 24 kHz and base64-encoded for Realtime events. The microphone stream is never passed to `addTrack`, `addTransceiver`, or another `RTCRtpSender`. The peer contains only a recvonly audio transceiver and the ordered data channel. Remote RTP is assigned to a hidden audio element owned by the controller.

The WebRTC sequence is complete ICE offer → `voice.start({ sdp, consumerId, foregroundSessionId? })` → install answer → wait for data-channel open and bounded `voice.status` polling with `sidebandReady`. Each phrase claims a fresh Host response epoch, then sends `input_audio_buffer.clear` → zero or more `append` events → `commit` → `response.create` carrying that epoch. Buffered-amount high/low water marks pause and resume appends. A completed final `response.done` marks generation complete but does not finish the phrase until the matching `output_audio_buffer.stopped`; playback drain returns the controller to idle while the WebRTC peer, data channel, Host sideband, provider conversation, process-global lease, and accumulated cost remain live. During generation or playback, another push-to-talk gesture or hands-free wake immediately pauses the local audio element, clears provider output even after generation has finished, cancels a provider response only while it remains open, and retires the old epoch. Existing microphone capture opens the replacement gate before the Host claim resolves, preserving a short voiced correction; commit and `response.create` remain fenced by the new Host owner, and a second output clear removes audio that raced that claim. A tool-only `response.done` leaves background Session work running but is not an active provider response, so a new phrase does not issue an invalid cancel or close the call. Late creation, completion, transcript, playback, error, timer, and Host tool-continuation work from a retired epoch cannot mutate or finish the new phrase, and an interrupted completion announcement is not queued for replay. Manual cancellation, fatal transport/provider failure, disposal, microphone-owner transfer, and Host expiry close the call. A completed tool response removes the ordinary spoken-response timeout because approval and Harness tools may remain pending; explicit cancellation and the Host maximum remain authoritative. When retired Session work settles, the addressed completion queue claims a fresh epoch, asks the Realtime shell to retrieve the exact request result, announces its Session, and asks before navigation; several completions are spoken serially without replacing the call.

The sidebar launcher remains visible in both the wide sidebar and its compact rail. It shows voice availability, opens the standard voice panel in the composer dock above the input card, and closes that panel when selected again. The persisted disclosure mode starts as `auto`, which keeps the idle panel closed and opens it when response text or an allowlisted Realtime operation appears; an explicit close or open survives activity updates, interruption, idle return, remount, and reload. Response text and every cost value render only inside the composer panel. The panel keeps the latest six ordered operations, marks current and completed steps, shows the bounded `thread_turn` prompt being prepared for the target Session, and retains the final spoken transcript until the next phrase or cancellation. It does not expose hidden reasoning, raw tool results, provider errors, or Session history.

Hands-free activation is always a user gesture: it acquires the microphone and enables the injected `ctx.wakeWord` service. Original Float32 worklet frames are fed locally before voice resampling. Only a provider detection whose literal keyword is `БРО` opens the phrase gate; local RMS VAD closes it. An accepted detection plays at most one local confirmation tone before gate setup, while duplicate detections rejected by the gate lifecycle remain silent. Playback is enabled by default, can be disabled independently in Voice Settings, persists in browser storage, and cannot block the accepted wake when audio output fails. The package does not claim universal keyword recognition. Voice Settings exposes initial calibration for an unready matcher and recalibration for a ready matcher. Starting either Settings transaction takes exclusive microphone ownership and disables hands-free detection; the user records the provider-required number of isolated `БРО` samples, and the wake provider atomically replaces the prior derived templates only after the required count commits. Raw calibration PCM exists only in bounded in-memory arrays, is zeroed after staging, and is never persisted; the provider persists derived templates only.

The single voice controller and the Settings calibration controller share one microphone coordinator. HMR/plugin disposal unsubscribes wake, Session-selection, creation, navigation, and completion listeners and stops tracks, worklet nodes, `AudioContext`, data channel, peer, timers, Blob URL, audio element, local buffers, and the Host voice call. Host stop rejection is contained as a generic connection failure and cannot prevent local media cleanup or coordinator release. The plugin never calls `wakeWord.dispose()` because Cordis owns the provider service.

Provider data-channel input is parsed as untrusted JSON. The UI accepts only known lifecycle and string transcript fields. Provider error messages and status details are discarded and mapped to localized generic error codes.

The controller prices only complete provider-reported token usage. `response.done` usage uses the official `gpt-realtime-2.1-mini` text, audio, and modality-specific cached-input rates, while input-transcription completion uses the separate `gpt-4o-mini-transcribe` rates. Cached tokens remain a subset of modality input and are charged once. Integer nano-US-dollar accumulators retain the latest committed phrase and global call totals across transport teardown, split into audio, text, cache, and transcription categories. Committed input-item and response-epoch ownership keeps late usage from an interrupted phrase in the call total without adding it to its replacement. The expanded voice plaque is the only cost display and contains request and call totals plus category detail. It validates total/category/reporting relations before rendering and logs rejected accounting or display updates without exposing provider details; malformed, incomplete, duration-based, absent, or inconsistent usage is not estimated. Rate sources are the OpenAI [model pricing](https://developers.openai.com/api/docs/models/gpt-realtime-2.1-mini), [transcription pricing](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe), and [Realtime cost guide](https://developers.openai.com/api/docs/guides/realtime-costs).

## Configuration

The browser plugin validates deployment tunables through `Config`: `maxBufferedChunks`, `channelHighWaterBytes`, `channelLowWaterBytes`, `statusAttempts`, `statusIntervalMs`, `iceTimeoutMs`, `channelTimeoutMs`, `responseTimeoutMs`, `vadThreshold`, `vadSilenceMs`, and `wakeSignalDefault`. The signal default is `true`; an explicit browser preference overrides it. The low buffered-amount mark must remain below the high mark. Host session expiry and provider protocol constants are not browser tunables.

The `/client` public API contains only Cordis loading values (`apply`, `inject`, `Config`), the settings-store factory needed for derived component props, and shared types. Components, protocol helpers, adapters, and audio utilities remain package-internal.

## Model Experience

### Gated Realtime audio

#### What the model sees

After local wake or push-to-talk activation, `VoiceSessionController` sends bounded PCM append events to the Host-selected global Realtime call. Foreground Session changes and navigation acknowledgements add no model content. For an addressed background completion, the controller adds one bounded system message containing only the request id, Session id, title, and terminal state; it tells the Realtime shell to retrieve the result through `wait_for_thread`, summarize it, and ask before navigation. The Host provider owns transcription, result text, and thread routing.

#### Token effect

No direct text tokens. The selected Realtime provider may tokenize or otherwise meter gated audio and its transcript independently; pre-trigger local audio contributes nothing.

#### KV Cache effect

The ordinary DSH Agent request prefix is unchanged until the Host provider submits an ordinary follow-up. The Realtime provider retains an independent call context across foreground Session changes; this browser package does not control that cache, but its cost meter reports cached-input usage when the provider includes complete modality details.

## Known Limitations and Deferred Work

- Wake recognition is browser-profile, speaker, microphone, and room dependent. Calibration-required is a first-class state, not an error or a promise that three samples produce production-grade keyword spotting.
- Calibration templates are local to the wake provider's browser storage and do not synchronize across browsers.
- The live WebRTC call is not resumable across page reload; only browser-local preferences and wake templates persist.
- The provider call retains short-term Realtime conversation context only until manual cancellation, fatal failure, disposal/reload, microphone-owner transfer, or Host expiry. Ordinary target-Session work remains durable under the normal Session log and memory paths.
