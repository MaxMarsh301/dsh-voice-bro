# `@deepseek-ai/dsh-voice-openai-realtime`

English | [中文](README.zh.md)

OpenAI Realtime provider for the Host-global `ctx.voice` lease. It exchanges one browser SDP offer through `POST /v1/realtime/calls`, returns the SDP answer immediately, then activates an authenticated server sideband with bounded retries. One process admits one active logical call, addressed to its browser tab by `consumerId`; provider call ids remain private.

## Configuration

Defaults are `gpt-realtime-2.1-mini`, `gpt-4o-mini-transcribe`, voice `cedar`, a 3300-second maximum session, 768 maximum output tokens per Realtime response, a 30-second sideband WebSocket ping interval, a 5-second browser-navigation acknowledgement timeout, and a separate 30-second Session-creation acknowledgement timeout. Model, transcription, and voice values use hard allowlists. `maxSessionSeconds`, `maxResponseOutputTokens`, `httpTimeoutMs`, `sidebandPingIntervalMs`, `activationAttempts`, `activationRetryMs`, `navigationAckTimeoutMs`, and `creationAckTimeoutMs` are bounded deployment settings; the sideband interval accepts 5,000 through 300,000 milliseconds and creation acknowledgement accepts 100 through 120,000 milliseconds. Optional `proxyURL` accepts an absolute credential-free HTTP or HTTPS CONNECT proxy URL and routes both call creation and the authenticated sideband WebSocket through that proxy.

`OPENAI_API_KEY` is resolved for every `start` through optional `ctx.credentials`, falling back to the process environment. Requests reject redirects, carry a `consumerId`-derived pseudonymous `OpenAI-Safety-Identifier`, and never include provider bodies or credentials in errors.

The realtime session uses PCM16 at 24 kHz in both directions, browser `recvonly` output, disabled automatic turn detection, and audio output. Its controlled tools are `find_threads`, `read_thread`, `create_thread`, `switch_thread`, `thread_turn`, `wait_for_thread`, `cancel_thread`, and `get_voice_status`. `create_thread` sends an addressed browser command that uses the canonical Workspace-backed Session creation path, optionally applies a user title, and commits voice foreground only after the browser confirms the observable current selection. It waits up to `creationAckTimeoutMs`; a missing acknowledgement returns `disposition: 'outcome_unknown'` without `created` or `activated`, because the browser operation can still complete after the Host deadline. The call retains up to 128 non-waiting creation records: a late acknowledgement stores the final result, an identical repeated acknowledgement succeeds idempotently, and a conflicting repeat is rejected. Active creation waits are never evicted. `switch_thread` resolves title queries inside the ordinary Sessions visible to `ctx.sessionQuery`; multiple matches return bounded choices without navigation, and an exact selected Session id is required after user confirmation. Session discovery and bounded reads use `ctx.sessionQuery` without resuming an Agent. `find_threads` always matches Session titles, workspace basenames, and ids; it adds event-content matches when the deployment enables full-text search, while `openAt: 'never'` leaves title discovery available. An empty query observes last event times before sorting and limiting, so an older Session with recent activity remains in the recent list; `has_more` counts only rows eligible for the requested running state. Turn and cancellation operations resolve ordinary live or persisted sessions through `ctx.typert.lookups.get('agent')`, reusing the deployment's configured cold-session resolver; subagent-owned sessions reject as unsupported.

`thread_turn` pins each accepted operation to its Session and fresh message identity before delivery. `wait_for_thread` follows that exact `MessageId` into its durable `user/message`, captures assistant text only from the matching Turn, and settles on the matching `turn/end`; whole-Agent idle is used only to report a delivered message that disappeared before entering a Turn. `reveal=immediately` or `reveal=on-complete` emits `voice/navigation-requested` for the owning `consumerId` and waits up to `navigationAckTimeoutMs` for `ackNavigation`. A timeout returns `activated: false` and never lets the shell claim that the thread is visible.

The browser claims a fresh response epoch before every phrase and carries it in `response.create` metadata. The sideband maps provider response ids to that epoch; every function call captures its response owner, and serialized output rechecks the current Host epoch immediately before writing `function_call_output` and its metadata-preserving continuation. Barge-in therefore suppresses delayed tools from the retired response while the same WebRTC call retains short-term conversation context. A retired `wait_for_thread` never performs delayed `reveal=on-complete` navigation. Its settled request instead emits one addressed `voice/completion-requested` signal; the owning browser claims a fresh epoch, starts a notification response on the existing call, and the shell retrieves the exact retained result through `wait_for_thread`, announces the Session, and asks before `switch_thread`. Several Session requests and completion signals remain independently keyed by request id. Function call ids remain deduplicated, so long `wait_for_thread` and navigation waits do not block status, cancellation, or another tool. WebSocket protocol pings keep the authenticated sideband active while those waits produce no application traffic. Stop, expiry, sideband failure, or plugin disposal first silence late work, settle internal waiters, stop the heartbeat, clear navigation timers, release the global lease, and close provider resources without waiting for Agent work. A start request that arrives while the prior call is already stopping joins that teardown before acquiring the lease. A reconnect from the same browser-tab `consumerId` waits for any pending start, tears down its orphaned active call, and acquires a fresh lease; a different consumer still cannot replace an active or pending call.

## Model Experience

### Realtime voice-shell request

#### What the model sees

The independent Realtime request receives the Russian `VOICE_CORE` instruction, user audio and transcription, and eight controlled function schemas. It can see at most ten bounded thread summaries, at most twelve user/assistant messages and 10 KiB of text from one explicitly selected ordinary thread, bounded status/request facts, one bounded browser completion message containing request and Session metadata, and at most 16 KiB of one matched Turn's assistant text. It receives no DSH tool schemas, tool results, provider ids, pre-trigger audio, complete session corpus, or subagent transcript. Each Realtime response is capped by the configured output-token limit.

##### `VOICE_CORE`

```markdown
Ты — глобальная голосовая оболочка DSH. Не добавляй к запросу служебные пояснения, мета-инструкции или слова, которых пользователь не произносил. Тред — это Session: находи его через find_threads, читай только явно выбранный тред через read_thread и не угадывай при неоднозначности. create_thread создаёт Session через обычный браузерный путь и активирует её только после подтверждённого успеха. Для переключения используй switch_thread: сначала передай произнесённое название в query; если возвращено confirmation_required, перечисли варианты и дождись явного выбора пользователя, затем передай session_id выбранного варианта. Не выдавай неоднозначный выбор за подтверждённый. Для содержательной работы вызывай thread_turn, затем wait_for_thread с полученным request_id. Пользователь может прервать ожидание, запустить работу в других тредах и продолжить голосовой разговор; не считай это ошибкой и не отменяй уже запущенные запросы. Пустой session_id означает foreground_session_id из get_voice_status; если его нет, попроси пользователя выбрать тред. mode=steer корректирует активную работу, mode=followup ставит отдельный запрос, mode=replace допустим только после явной просьбы прервать текущую работу. switch_thread открывает тред в браузере, но утверждай, что он открыт, только когда activated=true. Не открывай завершившийся тред без подтверждения пользователя: сначала назови сессию, кратко озвучь результат и спроси, переключить ли браузер на неё. Не заявляй о завершении до результата wait_for_thread. Если требуется подтверждение на экране, скажи об этом и продолжай ждать. После результата произнеси по-русски максимум 45 слов в двух-трёх коротких предложениях: итог, важное ограничение или следующий шаг. Не зачитывай списки, код, логи и подробности; скажи, что полный ответ доступен на экране только если activated=true.
```

#### Token effect

The Realtime model has an independent audio request containing the fixed instruction and eight schemas, followed by transcription, bounded function calls/results, and spoken output. `find_threads` and `read_thread` add only their bounded result to that request. An accepted `thread_turn` adds an ordinary follow-up or steering message to the selected DSH Agent; replace also cancels existing work first. The target Agent retains its normal context and tools.

#### KV Cache effect

The Realtime request has an independent cache lifetime; changing the model, instruction, or schemas invalidates its reusable prefix. Audio and function traffic grow after that prefix. The selected DSH Agent cache changes as for an ordinary follow-up, steering input, or cancel-and-replace sequence; Realtime audio, provider transcripts, thread lists, and read excerpts never enter its request.

## Known Limitations and Deferred Work

- **Ordinary sessions only** — discovery, reading, creation, switching, turn delivery, and cancellation exclude subagent Sessions until a dedicated subagent delivery and result-ownership design exists.
- **One process-global lease** — the provider admits one active call but does not persist or resume WebRTC state across process or browser reloads.
- **Consumer-owned browser peer** — signaling orchestration, `consumerId` lifecycle, microphone capture, barge-in, playback, navigation execution, and acknowledgements remain browser Consumer responsibilities.
- **Terminal activation failure** — exhausted sideband retries remove the logical call; a later status request returns `session not found`.
